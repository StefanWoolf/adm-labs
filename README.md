## Лабораторная работа 1. Воспроизводимость и пайплайн
1. Создана структура проекта, Git, `.gitignore`, виртуальное окружение, `requirements.txt`.
2. Датасет сохранён в `data/raw/titanic.csv` и добавлен в DVC (`dvc add`). Пропуски есть в самих данных (`age` — 177, `embarked` — 2).
3. Разбиение 80/20 со стратификацией, `random_state=42`.
4. Пайплайн: `MissingRowFlag` → `ColumnTransformer` (числа: медиана + StandardScaler; категории: мода + OneHotEncoder(handle_unknown='ignore'); `has_missing` — passthrough) → `LogisticRegression`.
5. Кастомный трансформер `MissingRowFlag` (BaseEstimator + TransformerMixin) добавляет бинарный признак «в строке есть пропуск». Он стоит до импутации.
6. GridSearchCV по `C` ∈ {0.01, 0.1, 1, 10}, 5 фолдов.

| | Значение |
|---|---|
| Лучший `C` | 1 |
| CV ROC-AUC (train) | 0.853 |
| Test ROC-AUC | 0.844 |
| Test accuracy | 0.810 |

Модель: `models/lab1_logreg.joblib` (под DVC).
**Вывод:** весь препроцессинг находится внутри Pipeline и обучается только на train, поэтому утечки из теста нет. Данные и модель версионируются DVC, код версионируется Git.

## Лабораторная работа 2. Инженерия признаков и отбор
Методы по варианту: импутация Simple (медиана) / KNN / Iterative; выбросы — IsolationForest; отбор — Mutual Information + Lasso (L1).
Все сравнения проводятся на 5-фолдовой стратифицированной CV по train (ROC-AUC). Test использован один раз, в финале.

| Этап | CV ROC-AUC | std |
|---|---|---|
| Импутация: Simple (median) | 0.8532 | 0.022 |
| Импутация: KNN (k=5) | 0.8527 | 0.024 |
| Импутация: Iterative | **0.8542** | 0.022 |
| + удаление выбросов (IsolationForest, 5%) | 0.8515 | 0.019 |
| + генерация признаков (family_size, fare_per_person, PolynomialFeatures(2)) | 0.8393 | 0.036 |
| + отбор MI (top-10) | 0.8291 | 0.026 |
| + отбор Lasso (L1) | 0.8487 | 0.028 |
| **Финал (GridSearchCV)** | **0.8590** | — |
| **Финал, test ROC-AUC** | **0.8638** | — |

Лучшая конфигурация по GridSearch: Iterative-импутация, генерация признаков, **без** удаления выбросов, отбор Lasso (L1), `C=0.1`.

**Выводы**
- Методы импутации различаются меньше, чем на std. Пропуски есть только в `age`, а пол и класс важнее возраста. Тип пропусков — MAR: в 3-м классе 28% пропусков, в 1-м 14%, во 2-м 6%.
- Удаление выбросов не помогло. Выбросы в Titanic — это не ошибки, а реальные пассажиры (большие семьи, дорогие билеты), и их удаление лишает модель информации.
- 35 сгенерированных признаков без отбора ухудшают качество: появляется шум и мультиколлинеарность. Lasso убирает лишнее и возвращает качество. MI проиграл, потому что оценивает признаки по одному и взял в основном дублирующие друг друга производные `fare`.
- Наибольший прирост дала связка «генерация + L1-отбор + регуляризация» (подобранная через GridSearch): с 0.853 до 0.859 на CV и 0.864 на test.

Модель: `models/lab2_final.joblib` (под DVC).

**Выводы**
- Библиотеку выбирали между бустингами с параметрами по умолчанию. Разница между ними (≤0.012) меньше std по фолдам. Выбран LightGBM: он самый быстрый (CatBoost медленнее в 15–20 раз) и входит в стекинг по варианту.
- Наибольший прирост дала Optuna: с 0.869 до 0.890. Найденная конфигурация — много неглубоких деревьев с маленьким шагом, то есть сильная регуляризация, которая нужна на маленьком датасете.
- SHAP: `sex` ≫ `fare_per_person` > `pclass` > `age`. Сгенерированный в лабе 2 `fare_per_person` оказался вторым по важности: деревья нашли порог около 25–30. Видны дети (age < 10 → большой плюс), большие семьи (`family_size` ≥ 5 → минус) и взаимодействие пол × класс: женщинам 3-го класса пол помогает меньше. `sibsp`/`parch` почти не используются, их заменил `family_size`.
- Стекинг почти не превосходит одиночный LightGBM (+0.001), потому что базовые модели скоррелированы, а обучение в 100 раз дольше. Метамодель доверяет RF и LightGBM, а не LogReg.
- Взвешивание классов при дисбалансе 38/62 не меняет ранговые метрики (ROC-AUC, PR-AUC), но повышает F1 при пороге 0.5 (0.739 → 0.769) за счёт recall.
- Test ROC-AUC стекинга (0.842) ниже CV и ниже LogReg на том же test (0.864, см. справочную таблицу в ноутбуке). При 179 объектах 95% интервал ROC-AUC составляет ±0.07, поэтому эти различия не значимы. Сигнал в Titanic сосредоточен в нескольких признаках, и сложные модели не дают устойчивого выигрыша над хорошо настроенной линейной моделью.

## Лабораторная работа 4. Нейронные сети для табличных данных (вариант 12, часть B)
Ноутбук: `notebooks/lab4.ipynb`. Код сети: `src/nn.py` (`make_prep`, `TabularMLP`, `fit_mlp`, `predict_proba`, `hidden_repr`).

**Разбиение:** test (179) отложен так же, как в лабах 1–3. Train (712) делится на tr (569) для обучения и val (143) для ранней остановки и подбора гиперпараметров.

**Предобработка для сети:** числа (`age, sibsp, parch, fare, family_size, fare_per_person`) заполняются медианой и масштабируются `StandardScaler`. Категории (`pclass, sex, embarked`) заполняются модой и проходят Label Encoding (`OrdinalEncoder`). Коды служат индексами в `nn.Embedding` размера `min(50, (card+1)//2)`, индекс 0 зарезервирован под неизвестную категорию.

**Архитектура:** `[числа | эмбеддинги]` → (`Linear → BatchNorm → ReLU → Dropout`) × N → `Linear(1)`; `BCEWithLogitsLoss`, Adam, batch 64, ранняя остановка по val ROC-AUC (patience 20). Устройство выбирается автоматически: CUDA, если есть, иначе CPU. Сеть маленькая, поэтому на CPU она обучается за секунды.

**Подбор на валидации** (12 конфигураций): слои {(64), (128, 64), (128, 64, 32)} × dropout {0.2, 0.4} × lr {1e-3, 3e-3}. Лучшая конфигурация: `(128, 64, 32)`, dropout 0.2, lr 3e-3, 36 эпох. Затем сеть заново обучается на всём train ровно столько же эпох.

| | val ROC-AUC | test ROC-AUC | test accuracy |
|---|---|---|---|
| LightGBM (default) | 0.858 | 0.825 | 0.804 |
| **MLP + Embedding** | 0.896 | **0.856** (0.849 ± 0.007 по 5 сидам) | 0.793 |

**PCA → t-SNE / UMAP** (`reports/lab4_embeddings.png`). Признаков меньше 50, поэтому PCA сохраняет все компоненты. Линейная разделимость оценивалась как test ROC-AUC логистической регрессии на PC1+PC2:

| Представление | Размерность | Дисперсия PC1+PC2 | LogReg на PC1+PC2, test ROC-AUC |
|---|---|---|---|
| Исходные признаки (scaled + one-hot) | 14 | 62% | 0.678 |
| Скрытый слой MLP | 32 | 80% | 0.857 |

Модели: `models/lab4_lgbm.joblib`, `models/lab4_mlp.joblib` (препроцессор + конфигурация + `state_dict`), обе под DVC. Кривая обучения: `reports/lab4_learning_curve.png`.

**Выводы**
- MLP обошла LightGBM с параметрами по умолчанию (0.856 против 0.825 на test): дефолтный бустинг переобучается на 712 строках. Настроенный LightGBM из лабы 3 (CV 0.890) и LogReg из лабы 2 (test 0.864) сеть не превосходит. Все различия на test укладываются в 95% интервал (±0.07 на 179 объектах).
- Val ROC-AUC сети (0.896) завышен из-за выбора по той же валидации (лучшая из 12 конфигураций и лучшая эпоха). Честная оценка — test. Устойчиво видно только то, что однослойные сети хуже трёхслойных; остальные различия меньше шума валидации (≈0.03).
- Результат сети зависит от сида (±0.007), бустинг детерминирован. По accuracy сеть немного хуже, хотя ROC-AUC выше: ROC-AUC оценивает ранжирование, accuracy — один порог 0.5.
- `nn.Embedding` для категорий с 2–3 значениями почти эквивалентен one-hot. Эмбеддинги полезны для признаков с большим числом категорий.
- На исходных признаках PCA почти не разделяет классы (0.678): главные компоненты соответствуют дисперсии `fare` и размера семьи, а не полу. t-SNE/UMAP показывают много мелких кластеров из почти одинаковых пассажиров (дискретные признаки), классы перемешаны глобально.
- Скрытый слой сети почти одномерен: «шкала выживания», от женщин 1–2 класса (выживаемость 92–97%) до мужчин 2–3 класса (14–16%). Женщины 3-го класса (50%) и мужчины 1-го класса (37%) лежат посередине, на них модель и ошибается. Двух компонент PCA скрытого слоя хватает, чтобы получить качество всей модели (0.857).
- Расстояния между кластерами и их размеры на t-SNE/UMAP не интерпретируются: эти методы сохраняют только соседство точек.

## Лабораторная работа 5. Большие данные и AutoML (вариант 9)
Датасет: синтетический «финансовый», `make_classification` (30 признаков, 12 информативных, дисбаланс 80/20), 5 млн строк, цель `label`. Ноутбук `notebooks/lab5.ipynb`, общий код в `src/lab5.py`.

**Окружение.** Отдельный `.venv-lab5` на том же Python 3.13 (`requirements-lab5.txt`): AutoGluon 1.6.3 поддерживает 3.13, но требует `pandas<2.4`, а в основном окружении pandas 3.0. PyCaret 3.3 не ставится на 3.13 и тянет sklearn 1.4, поэтому выбран AutoGluon. Для PySpark 4.3 нужна Java 17/21. Проверка окружения: `python -m src.lab5 check`.

**Данные** (`python -m src.lab5 generate`, `data/raw/lab5_synth.parquet`, под DVC). `feat_00` превращён в сумму `amount`, добавлены `client_id`, `region`, `ts` (строкой). Внесены дефекты: 2% пропусков в 3 колонках, 0.5% дублей.

**PySpark** (`local[*]`): приведение типов (`ts` → timestamp), `dropDuplicates`, подсчёт пропусков. Разбиение 80/20 по хешу строки (`xxhash64`), воспроизводимо. Медианная импутация `pyspark.ml.feature.Imputer`, обученная на train. 11 новых признаков: `log_amount`; `hour`, `day_of_week`, `month`, `is_weekend`; групповые по клиенту `client_txn_cnt`, `client_amount_mean`, `client_amount_std`, `amount_to_client_mean`; `region_amount_mean`; `amount_missing`. Групповые статистики считаются по train и присоединяются broadcast-join. Схема и первые 10 строк: `reports/lab5_schema.txt`, `reports/lab5_head.csv`.

**AutoML.** AutoGluon `medium_quality`, `eval_metric="roc_auc"`, два запуска: `time_limit` 300 и 900 с. Обучение на подвыборке 1 млн строк из ~4 млн train; test (~1 млн) отложен. Исключены KNN/RF/XT: на 1 млн строк они занимают гигабайты памяти и медленно предсказывают.

**MLflow** (`mlflow.db` + `mlruns/`, эксперимент `lab5_variant9_synthetic_financial`): 3 запуска (baseline LogReg + 2× AutoGluon). Логируются параметры, версии библиотек, размеры данных, val/test-метрики, leaderboard, модель. UI: `mlflow ui --backend-store-uri sqlite:///mlflow.db`.

**Выводы**
- LogReg сильно проигрывает: в `make_classification` каждый класс состоит из нескольких гауссовых кластеров, граница нелинейная. AutoML за минуты без настройки находит ансамбль бустингов, и здесь он оправдан.
- Увеличение `time_limit` в 3 раза даёт прирост в тысячных долях ROC-AUC, то есть отдача от времени убывает.
- PySpark на одной машине и 5 млн строк скорее демонстрация: pandas справился бы. Но тот же код без изменений масштабируется на кластер, а ленивые вычисления, `cache` и `broadcast`-join позволяют обойтись без Python UDF.
